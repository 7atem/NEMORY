# VaultBrain Connected & Proactive Experience

## Multi-Bot Engineering Master Plan

# 0. PRODUCT GOAL

VaultBrain should evolve from:

```text
Capture
→ Understand
→ Store
→ Search
```

into:

```text
CAPTURE + CONNECT + OBSERVE
            ↓
     PERSONAL CONTEXT
            ↓
   UNDERSTAND WHAT MATTERS
            ↓
     CONNECT RELATED DATA
            ↓
      SURFACE IT AT THE
         RIGHT MOMENT
```

Examples:

```text
Amazon notification:
"Your package is 8 stops away"

        ↓

VaultBrain recognizes:
delivery update
+
existing product/order
+
personal collection

        ↓

Home:

📦 Bambu build plate
Arriving soon
8 stops away
```

Another example:

```text
Calendar:
Flight tomorrow

Gmail:
Hotel confirmation

Task:
Buy travel adapter

Vault:
Train ticket

        ↓

Europe Trip

Tomorrow:
✈ Flight
⚠ 1 task remaining
🏨 Hotel ready
🚆 Train saved
```

The user should NOT need to ask Brain before the app becomes useful.

# 2. CORE PRINCIPLES — ALL BOTS MUST FOLLOW

## 2.1 VaultItem is not ExternalRecord

```text
VaultItem
= something intentionally saved

ExternalRecord
= contextual information from a connected source
```

Never import every email/event/contact into the Vault.

---

## 2.2 Connectors are provenance, not organization

Never create the primary UI:

```text
Gmail
Calendar
Health
Tasks
Notifications
```

Instead:

```text
Today
Coming up
Needs attention
Your trips
Your projects
Recently changed
```

---

## 2.3 Personal Collections remain user organization

System source:

```text
GMAIL
CALENDAR
NOTIFICATION
```

must never become personal categories.

---

## 2.4 Gemma is not infrastructure

Gemma may:

```text
understand
summarize
resolve ambiguity
identify relations
generate brief explanations
suggest actions
```

Gemma must NOT:

```text
perform OAuth
query Gmail directly
calculate exact times
schedule workers
execute arbitrary actions
manage permissions
control synchronization
decide whether something is deleted
```

---

## 2.5 Kotlin remains authoritative

Use deterministic Kotlin for:

```text
dates
deadlines
time ranges
deduplication
permissions
sync cursors
notifications
action validation
importance scores where possible
```

---

## 2.6 No automatic destructive behavior

Never automatically:

```text
send email
delete email
delete Calendar event
create collection
move memories
create task
create Calendar event
```

without appropriate user confirmation.

---

# 3. BOT ORCHESTRATION RULE

## VERY IMPORTANT

Only ONE bot at a time should own:

```text
Room schema
database version
database migrations
shared integration models
```

Avoid multiple agents creating migrations simultaneously.

Parallel development becomes safer only after the foundation schema is committed.

---

# 4. DEVELOPMENT BRANCH / COMMIT STRATEGY

Before every bot starts:

```bash
git status
git log --oneline -10
```

Each bot must start from a clean checkpoint.

Never hand the next bot a broken uncommitted repository.

Recommended milestones:

```text
M0  P1 complete

M1  External Context Foundation

M2  Share Integration

M3  Calendar + Local Reminders

M4  Proactive Signal Engine

M5  Tasks + Gmail + Contacts

M6  Health + Notifications

M7  Cross-source Context + Daily Brief

M8  Release Hardening
```

```text
"I don't have to manually tell the app everything.
```

```text

proactive
contextual
private
local-first
controlled by the user
```

```text

a chatbot that only works when asked
```

The connectors are the sensors.

The context engine is the intelligence.
